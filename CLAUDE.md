# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Full Stack FastAPI Template: a FastAPI + SQLModel + PostgreSQL backend with a React/Vite/TypeScript frontend, built as a monorepo. The frontend is built and served by the FastAPI app itself (`app.frontend("/", directory=...)` in `backend/app/main.py`), not deployed separately.

## Commands

### Local development

```bash
docker compose up -d db mailcatcher   # start Postgres + Mailcatcher
cd backend
uv sync
uv run bash scripts/prestart.sh       # wait for DB, run alembic migrations, seed initial data
uv run fastapi dev                    # backend at :8000, docs at :8000/docs
```

```bash
bun install                           # from project root
bun run dev                           # frontend dev server at :5173
```

Full stack in Docker Compose instead (stop any locally running FastAPI dev server first, both use :8000):

```bash
docker compose run --rm backend bash scripts/prestart.sh
docker compose watch
```

### Backend (run from `backend/`)

```bash
uv run bash scripts/test.sh                          # full pytest suite w/ coverage (htmlcov/index.html)
uv run pytest tests/api/routes/test_items.py::test_x  # single test
uv run bash scripts/lint.sh                           # mypy, ty, ruff check, ruff format --check
uv run bash scripts/format.sh                         # ruff check --fix, ruff format
```

Against an already-running Docker Compose stack: `docker compose exec backend bash scripts/tests-start.sh [pytest args]` (e.g. `-x`).

### Frontend (run from project root unless noted)

```bash
bun run lint                                   # biome check --write --unsafe
cd frontend && bunx playwright test            # e2e; requires the stack running (see frontend/README.md)
cd frontend && bunx playwright test --ui
```

### Migrations (run from `backend/`, DB must be up)

```bash
uv run alembic revision --autogenerate -m "message"
uv run alembic upgrade head
```

Commit the generated file under `backend/app/alembic/versions/`.

### Generated OpenAPI client

After any backend API/schema change, regenerate the frontend client and commit the result:

```bash
bash ./scripts/generate-client.sh
```

### Pre-commit

Hooks run via `prek` (see `.pre-commit-config.yaml`): `uv run prek install -f` to enable on commit, `uv run prek run --all-files` to run manually. This chains ruff, mypy, ty, biome, typos, client generation, and more — prefer it over running individual lint commands when checking a change is clean.

## Architecture

### Settings and environment

A single root-level `.env` file (tracked in git with placeholder `changethis` values) is the source of truth for both Docker Compose variable interpolation and the backend. `backend/app/core/config.py` (`Settings`, pydantic-settings) reads it via `env_file="../.env"` — relative to `backend/`. `Settings._enforce_non_default_secrets` raises if `SECRET_KEY`, the DB password, or `FIRST_SUPERUSER_PASSWORD` are still `"changethis"` unless `FASTAPI_ENV=development` (then it only warns).

Compose files layer: `compose.yml` (base, always loaded) + `compose.override.yml` (dev-only: volume mounts, exposed ports, auto-loaded) + `compose.deploy.yml` (deploy-only: HTTPS/Traefik certs, must be combined explicitly).

### Backend (`backend/app/`)

- `models.py` — SQLModel classes double as both the DB schema (ORM) and API request/response schemas.
- `api/routes/` — one module per resource (`login`, `users`, `items`, `utils`); `private.py` is dev-only and only mounted when `FASTAPI_ENV=development` (see `api/main.py`).
- `crud.py` — DB access functions called from routes; keep DB logic out of route handlers.
- `core/db.py`, `core/security.py` — engine/session setup and password hashing/JWT.
- `alembic/` — migrations autogenerated from `models.py`.
- Frontend build output is copied to `backend/app/frontend/` (gitignored) and served from there in production.

### Frontend (`frontend/src/`)

- `client/` — generated OpenAPI client (do not hand-edit; regenerate via `scripts/generate-client.sh` after backend changes).
- `routes/` — TanStack Router file-based routes; `_layout/` holds authenticated-shell routes.
- `components/` — organized by feature (`Admin`, `Items`, `UserSettings`, `Sidebar`, `Common`, `Pending`), plus `components/ui` for shadcn/ui primitives.
- Data fetching via TanStack Query against the generated client.
- Talks to the backend at the same origin by default; set `VITE_API_URL` (e.g. in `frontend/.env`) to point the Vite dev server at a remote API.

### Email templates

Source components live in `packages/react-email/` (React Email). `backend/app/email-templates/` holds the generated HTML actually sent by the app and should not be hand-edited. Placeholders are Jinja (`{{ username }}`) declared as component props; the values passed to each template are built in `generate_*_email()` in `backend/app/utils.py` — adding a placeholder requires updating both. Preview with `bun run email:dev`; regenerate with `bun run email:export`.

### Deployment

Two paths, documented in `deployment.md` (FastAPI Cloud, via `.github/workflows/deploy.yml` on push to `master`) and `deployment-docker-compose.md` (self-hosted, `compose.yml` + `compose.deploy.yml` behind Traefik).
